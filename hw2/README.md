# ИДЗ-2 - сортировочная железнодорожная станция

Подлягин Данил Денисович, БПИ253. Вариант 49.

Консольная модель на C17 и pthread для Linux. Прибывающие составы
расцепляются, локомотивы перевозят вагоны по совместимым маршрутам, а из
накопленных вагонов формируются новые поезда.

## Сборка и запуск

Нужны компилятор C, make и стандартные Linux-утилиты timeout, awk и grep.
Из папки `hw2`:

```bash
make
./station
./station examples/parallel.scenario 100
```

Первый аргумент - файл сценария, второй - длительность единицы модельного
времени в миллисекундах: 1..1000, по умолчанию 100.
Табло обновляется в терминале, полная история записывается в `station.log`.
При перенаправлении вывода табло автоматически отключается.

Вторая программа, `station-cond`, принимает те же параметры. Она использует
условные переменные вместо семафоров; правила моделирования общие.

```bash
./station-cond examples/parallel.scenario 100
./station --scenario examples/parallel.scenario --strategy most --until 20
./station --quiet --log run.log
./station --help
```

`first` задаёт приоритет комплектов по порядку путей, `most` - по убыванию
вместимости их путей.
`--until N` ограничивает модельное время; 0 отключает ограничение.
Ctrl+C корректно останавливает участников и сохраняет частичный результат.

## Проверка

```bash
make test
make clean
```

Тесты проверяют обе реализации: разбор данных, состояния вагонов,
планирование комплектов, совместимость маршрутов, вместимость, остановку и
ошибки запуска. Сообщения об ошибках для намеренно неверных входов ожидаемы.

В `examples/` четыре примера: station - обычная работа, parallel - независимые
манёвры, conflicting - конфликт маршрутов, remainder - невыполнимый остаток.
Служебные сценарии регрессионных проверок находятся отдельно в `test-data/`.

Коды завершения: 0 - все вагоны отправлены; 1 - ошибка; 2 - лимит времени;
3 - нарушение инварианта; 4 - невыполнимый остаток; 5 - сигнал.

Устройство модели, формат сценария и ограничения описаны в [REPORT.md](REPORT.md).
