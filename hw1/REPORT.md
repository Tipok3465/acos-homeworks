# Индивидуальное домашнее задание № 1

## 1. Границы модели

Программа показывает работу станции от прибытия исходных составов до отправки
всех поездов, которые возможно собрать. Вагоны расцепляются, ожидают решения
диспетчера и по одному перемещаются маневровыми локомотивами на пути своего
направления. Накопив требуемый комплект, станция формирует новый поезд.

В модели учитываются:

- назначение и вместимость путей;
- состав и время прибытия исходных поездов;
- направление каждого вагона;
- скорость и занятость локомотивов;
- длина и взаимные конфликты соединительных маршрутов;
- длительности расцепки, сцепки и манёвра;
- требования к отправляемым поездам;
- стратегия выбора сортировочного пути.

Это последовательная дискретная имитация. Параллельные по смыслу операции
представлены состояниями сущностей, но вычисляются одним процессом и одним
потоком.

## 2. Язык входного сценария

Исходные данные отделены от исполняемого файла и задаются строками вида
`ключ=значения`:

```text
track=id,purpose,capacity
locomotive=id,speed
route=id,from_track,to_track,length,conflict|conflict
wagon=id,arrival_id,destination
arrival=id,time,track
requirement=id,destination,wagon_count,track
timing=uncoupling,coupling,maneuver
strategy=first_fit
```

Для маршрута без конфликтов последнее поле равно `-`. Альтернативная стратегия
записывается как `strategy=most_free_capacity`.

Пример минимального фрагмента:

```text
track=1,arrival,8
track=2,north,4
locomotive=1,5.0
route=1,1,2,100.0,-
wagon=1,10,north
arrival=10,0,1
requirement=101,north,1,2
timing=2,2,4
strategy=first_fit
```

Загрузчик не начинает моделирование, пока не проверит весь файл. Отклоняются
неизвестные ссылки, повторяющиеся идентификаторы одного вида, неположительные
размеры и длительности, отрицательное время прибытия, асимметричные конфликты,
недостижимые направления и требования, не совпадающие с назначением пути.

## 3. Жизненный цикл вагона

Центральная сущность варианта — вагон. Его положение однозначно задаётся одним
из пяти состояний:

```text
PLANNED -> WAITING -> MOVING -> SORTED -> DEPARTED
```

| Состояние | Смысл |
| --- | --- |
| `PLANNED` | состав ещё не прибыл либо расцепка не закончилась |
| `WAITING` | вагон доступен диспетчеру |
| `MOVING` | вагон закреплён за одним локомотивом |
| `SORTED` | вагон занимает место на сортировочном пути |
| `DEPARTED` | вагон включён в отправленный поезд |

Смена состояния выполняется только моделью. Благодаря этому один вагон не
может одновременно находиться в составе, на пути и у локомотива.

## 4. Модельное время и события

Один проход цикла равен одной единице модельного времени. Внутри шага операции
имеют фиксированный порядок:

1. завершение манёвров;
2. регистрация прибытий;
3. окончание расцепки;
4. начало манёвров после сцепки;
5. отправление готовых поездов;
6. новые назначения диспетчера;
7. контроль инвариантов и условия остановки.

Временная цепочка одного вагона выглядит так:

```text
ARRIVE
   | uncoupling
UNCOUPLE -> ASSIGN -> RESERVE
                         | coupling
                       START
                         | maneuver
                    FINISH -> PLACE
                                  | enough wagons
                              FORM -> DEPART
```

Несколько строк могут иметь одинаковое поле `time`. Они относятся к одной
модельной отметке и выводятся по очереди лишь потому, что программа
последовательная. Задержка интерфейса влияет только на скорость наблюдения.

Фактическое время движения вычисляется как:

```text
max(configured_maneuver, ceil(route_length / locomotive_speed))
```

До него добавляется заданная длительность сцепки. Поэтому скорость локомотива и
временные параметры сценария одновременно участвуют в расчёте.

## 5. Ресурсы и решение диспетчера

Для ожидающего вагона диспетчер последовательно ищет:

1. путь с совпадающим назначением и свободным местом;
2. незанятый локомотив;
3. маршрут от пути прибытия к выбранному пути;
4. отсутствие активного конфликтующего маршрута.

При оценке вместимости считаются как размещённые вагоны, так и вагоны, уже
направленные к пути. Это не позволяет двум локомотивам зарезервировать последнее
место одновременно.

Режим `first_fit` выбирает первый допустимый путь. Режим
`most_free_capacity` сравнивает остаточную вместимость. Маршрут резервируется на
период сцепки и движения, после размещения вагона резерв снимается.

Новый поезд отправляется только при наличии точного числа вагонов требуемого
направления на указанном пути. В поезд не попадают вагоны другого назначения.

## 6. Устройство программы

| Компонент | Ответственность |
| --- | --- |
| `station.h` | сущности станции, ограничения массивов и публичные функции |
| `config.c` | значения запуска по умолчанию и разбор аргументов |
| `main.c` | сигналы, загрузка сценария, журнал и код возврата |
| `simulation.c` | парсер сценария, часы модели, диспетчер, табло и статистика |
| `tests.c` | проверки конфигурации, данных, инвариантов и завершения |

Предметные участники представлены независимо:

- `Arrival` описывает прибывающий состав;
- `Wagon` хранит направление и текущее состояние вагона;
- `Locomotive` хранит выполняемую операцию и моменты её начала и конца;
- `Track` отвечает за назначение и вместимость пути;
- `Route` хранит топологию и конфликтующие участки;
- `Requirement` описывает будущий поезд;
- функции `choose_track`, `route_available` и `dispatch` реализуют диспетчера.

Такое разбиение сохраняет самостоятельность участников модели без создания
лишних процессов, потоков или универсальной событийной платформы.

## 7. Наблюдаемое поведение

Интерфейс выполнен как англоязычное терминальное табло. После предметного
события оно показывает историю текущего кадра и состояние ресурсов. В конце
появляется итоговый блок с причиной остановки, модельным временем, числом
манёвров, ожиданием, отправленными вагонами и загрузкой ресурсов.

Полный набор событий:

| Событие | Что произошло |
| --- | --- |
| `ARRIVE` | состав прибыл |
| `UNCOUPLE` | вагон отделён от состава |
| `ASSIGN` | выбраны локомотив и целевой путь |
| `RESERVE` | занят соединительный маршрут |
| `START` | началось перемещение |
| `FINISH` | перемещение завершилось |
| `PLACE` | вагон поставлен на путь |
| `FORM` | собран требуемый комплект |
| `DEPART` | новый поезд отправлен |

Экранная пауза по умолчанию равна 1000 мс. Машинно-читаемый журнал пауз не
содержит и сохраняет всю историю независимо от перерисовки терминала.

Сценарий открывается через `open`, после чего разбирается посредством
`fdopen`/`fgets`. Для журнала используются файловый дескриптор и `dprintf`.

## 8. Контроль безопасности модели

После каждого шага `validate_state` сверяет сохранённые значения с фактическим
состоянием массивов. Проверяются:

- вместимость пути вместе с входящими вагонами;
- совпадение счётчика пути с числом размещённых вагонов;
- допустимость пары «состояние вагона — его местоположение»;
- наличие не более одного вагона у локомотива;
- согласованность вагона и локомотива;
- невозможность одновременного резервирования конфликтующих маршрутов.

Ошибка порождает событие `INVARIANT` и отдельный код завершения. Проверка служит
страховкой самой модели, а не способом исправлять некорректный сценарий: ошибки
входного файла обнаруживаются раньше.

## 9. Почему выполнение заканчивается

Каждый корректный конечный сценарий приходит к одному из трёх предметных
результатов: отправлены все вагоны, остался невыполнимый набор либо достигнут
заданный предел времени. Время прибытия неотрицательно, а длительности операций
конечны и положительны. Если нет будущих вагонов и активных манёвров, продолжать
цикл бессмысленно — фиксируется остаток.

Пользователь может остановить безлимитный запуск с помощью `Ctrl+C`. Обработчик
`SIGINT`/`SIGTERM` меняет только атомарный флаг. Завершение, вывод статистики и
закрытие файла выполняются позже в безопасной точке основного цикла.

| Код | Результат |
| ---: | --- |
| 0 | вся работа выполнена |
| 1 | аргументы, входной файл или операция ОС завершились ошибкой |
| 2 | достигнута граница `--until` |
| 3 | обнаружено нарушение инварианта |
| 4 | дальнейшее формирование поездов невозможно |
| 5 | получен сигнал остановки |

## 10. Проверка реализации

Команда `make test` выполняет 14 автоматических проверок. Они охватывают CLI,
корректный и ошибочные сценарии, временные параметры, ссылки между сущностями,
дубликаты, отрицательное время, вместимость, конфликты, успешный результат,
остаток, ограничение времени и прерывание.

Команда `make examples` запускает три демонстрации и сверяет временные отметки
`UNCOUPLE`, `ASSIGN`, `START` и `FINISH` в сохранённом журнале.

Полученные результаты:

| Набор | Время | Манёвры | Итог |
| --- | ---: | ---: | --- |
| `station.scenario` | 42 | 2 | отправлены 2 вагона и 2 поезда |
| `multi.scenario` | 51 | 3 | отправлены 3 вагона и 2 поезда |
| `remainder.scenario` | 14 | 1 | корректно диагностирован остаток |

Отдельные файлы проверяют отсутствие `timing`, неизвестный состав,
отрицательное прибытие, повтор ID и резервирование последнего места на пути.
Сборка выполняется с `-Wall -Wextra -Wpedantic -Werror`. Дополнительно проект
проверен AddressSanitizer и UndefinedBehaviorSanitizer.

## 11. Воспроизведение

```bash
make
./station --scenario examples/station.scenario --log station.log
```

Полезные варианты:

```bash
# Без задержки интерфейса
./station --delay-ms 0

# Другая стратегия и другой набор данных
./station --scenario examples/multi.scenario --strategy most

# Ограниченный запуск
./station --until 10

# Полная самопроверка
make test
make examples
```

Артефакты сборки удаляются командой `make clean`.
